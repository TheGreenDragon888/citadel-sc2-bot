## 5. Tuning many numeric parameters from noisy win/loss results

Binary-outcome noise: one game's result has SD 0.5 (win rate at p=0.5), so 1000 games give +/-3.1 percentage points (95%), roughly +/-22 Elo (computed in section 6, script /tmp/claude-0/-home-user-citadel-sc2-bot/cc35ec4c-9b29-5d67-891d-a94a0ceb8ff8/scratchpad/research/stats.py).

- **SPSA** (Spall). Each iteration perturbs all parameters at once by +/-c_k (random signs), plays the two perturbed versions against each other (Stockfish: a pair of games), and steps along the sign of the result with gain a_k; gains decay as a_k = a/(k+1+A)^alpha, c_k = c/(k+1)^gamma, Spall's alpha=0.602, gamma=0.101. [Verified] https://www.chessprogramming.org/SPSA
  - Dimension: gradient estimate costs 2 evaluations regardless of the number of parameters, so it is the standard choice for tens to hundreds of parameters. Historical: Stockfish tuning sets of 7-30 variables used up to ~100,000 games per set [Verified, forum post by J. Kiiski quoted via search result https://talkchess.com/viewtopic.php?p=427840 , secondary]; a 2021 net-tuning run used 800k games [Uncertain, secondary: https://m.nextchessmove.com/dev-builds/49283d3a6676e114b531d6a8b9e5f69000655912].
  - Fishtest practice: user enters initial value, min, max, final c and final r per parameter; iteration = 2 games; number of games is fixed at start because schedules depend on it; "A good tune run exhibits a significant change in the tuned values while minimizing random change"; stop a run if values barely move after a few thousand games (c too low); integer parameters need c > 1 (scale up). No recommended max number of parameters; tuning many values at once "tends to produce random change". [Verified] https://github.com/official-stockfish/fishtest/wiki/Creating-my-first-test . Fishtest FAQ: tuning runs use fixed 20000 games at TC 10+0.1, then confirm with a two-stage SPRT. [Verified] https://github.com/official-stockfish/fishtest/wiki/Fishtest-faq
  - Failure modes: sensitive to a/c/A choice; too few games per iteration; parameters rarely exercised (never move); clipping at min/max; random drift when too many parameters are weakly relevant; no built-in stopping criterion. [Verified: chessprogramming SPSA page + fishtest wiki above]
  - Fishtest also uses workers in parallel with out-of-order updates (asynchronous SPSA). [Verified] https://official-stockfish.github.io/docs/fishtest-wiki/Fishtest-Mathematics.html
- **SPRT** (Wald; fishtest uses GSPRT with normalized Elo). Tests H0: Elo gain = elo0 vs H1: elo1 with error rates alpha, beta, playing until the log-likelihood ratio hits a bound; this minimises expected games for a given error rate. It tests one change, not many parameters. [Verified] https://www.chessprogramming.org/Sequential_Probability_Ratio_Test ; https://official-stockfish.github.io/docs/fishtest-wiki/Fishtest-Mathematics.html . Bounds commonly used for gainers: [0,5] top-30 engines, [0,10] others, [0.5,2.5] weak. [Verified, same CPW page]
  - Games needed (my calculation, binary win/loss, no draws, alpha=beta=0.05, Wald approximation, expected at the true value being either hypothesis): bounds [0,5] ~25,600 games; [0,10] ~6,400; [0,20] ~1,600; [0,50] ~260. [Computed, Likely; stats.py] SC2 has almost no draws, so these are larger than chess numbers with many draws.
  - Failure modes: stops early on lucky streaks if used repeatedly without correcting for multiple tests (every extra SPRT you run is another chance of a false pass); needs a pool/opponent-mix that stays fixed during the test. [Likely]
- **CLOP** (Coulom). Fits local quadratic regression of win rate vs parameters and prunes samples "confidently inferior to the mean", sampling the promising region more. Written for tuning game programs from win/loss. Paper claim: "when the function to be optimized is smooth, this method outperforms all other tested algorithms". Number of parameters and games not stated on the page. [Verified for description] https://www.remi-coulom.fr/CLOP/ . Known to degrade as dimension grows (quadratic model needs O(d^2) samples). [Likely, from method; Uncertain as published number]
- **Bayesian optimisation / Optuna TPE.** TPE fits one density to best trials and one to the rest and favours parameters where the ratio is high; default 10 random startup trials; `multivariate` defaults True; `constant_liar` for parallel workers. Docs give no guidance for high-dimension or noisy objectives. [Verified] https://optuna.readthedocs.io/en/stable/reference/samplers/generated/optuna.samplers.TPESampler.html . Practical limit: effective for roughly <=20 parameters with low noise; with one binary game per trial the noise swamps it, so each trial needs batches (hundreds of games). [Likely, general knowledge, no primary number]
  - Failure modes: noise treated as signal, winner's curse (best-looking trial is overfitted; re-validate); budget wasted on irrelevant dimensions. [Likely]
- **CMA-ES** (Hansen). Samples a population from a Gaussian and adapts its covariance towards successful steps; for continuous, non-convex, rugged functions. [Verified abstract] https://arxiv.org/abs/1604.00772 . Population size, dimension limits and noise handling are in the full text, not read here: usual default population is 4+floor(3 ln n) and larger populations are advised for noisy objectives [Likely, from memory; Uncertain]. Needs ranking of candidates, so each candidate needs a batch of games.
  - Failure modes: with binary win/loss and small batches the rank noise is huge; costs scale as population x games-per-candidate x generations (e.g. 20 x 200 x 50 = 200k games). [Likely, arithmetic]
- **Population-based training** (Jaderberg et al.). Asynchronously trains a population and copies weights + perturbs hyperparameters from better members; designed for neural-net training and hyperparameters changing during training. [Verified abstract] https://arxiv.org/abs/1711.09846 . It optimises a changing schedule inside a training run, so for fixed constants in a rule-based bot it adds little over SPSA. [Likely]
- Net judgement for ~385 constants with ~1-2 percentage point signal: SPSA on groups of related parameters (tens at a time), then confirm with a fixed-N or SPRT match against a fixed opponent pool; keep the verification games separate from tuning games. [Likely, my synthesis]

## 6. Statistics

- Elo expected score: E = 1 / (1 + 10^(-(Ra - Rb)/400)); inverse: Elo diff = 400 log10(p/(1-p)). [Verified standard definition; AI Arena uses Elo, start 1600, K=16 per docs/RESEARCH.md:36-37] 
- Elo of win rate (equal-strength pool): 55% = +34.9 Elo; 60% = +70.4; 70% = +147.2. So a 50%->55% change is +35 Elo, 50%->60% is +70 Elo; near 50% each +1 percentage point is about 7 Elo. [Computed, Verified formula]
- Games to tell 50% from p1, 95% confidence, 80% power, normal approximation n = ((z_{a/2} sqrt(p0 q0) + z_b sqrt(p1 q1)) / (p1-p0))^2, z=1.96 and 0.8416: [Computed]
  - 55%: 783 games (two-sided, one sample vs known 50%); 617 one-sided. As A/B comparison of two noisy bots: 1565 per arm (3130 total).
  - 60%: 194 (153 one-sided); A/B 388 per arm (776 total).
  - 70%: 47 (37 one-sided); A/B 93 per arm (186 total).
  - In Elo terms vs a fixed 50% baseline: +10 Elo ~9,500 games; +20 Elo ~2,400; +50 Elo ~380 (one-sample two-sided). A/B of two unknown versions needs about double.
- Standard error of win rate at p=0.5: 100 games +/-9.8 pts (95%); 400 +/-4.9; 1000 +/-3.1; 4000 +/-1.5. [Computed]
- Ladder implication: Elo vs a 165-bot field is not a single-opponent win rate; ladder games are sparse and the pool changes, so local fixed-pool testing is the only way to resolve +10-20 Elo changes. [Likely]

## 8. Claude Code docs: headless, permission modes, Remote Control (read 2026-11-11)

Headless / non-interactive [Verified] https://code.claude.com/docs/en/headless
- `claude -p "<prompt>"` runs non-interactively; exit code 0 on success, non-zero on failure; `--output-format text|json|stream-json`; `--continue` / `--resume <session_id>` to continue; JSON output includes `total_cost_usd`.
- `--bare` is "the recommended mode for scripted and SDK calls" (skips hooks, skills, plugins, MCP, auto memory, CLAUDE.md; needs `ANTHROPIC_API_KEY`, no subscription login). Without `--bare`, `-p` runs project hooks and `.mcp.json` servers even in an untrusted folder.
- `--allowedTools "Bash(git diff *),Read,Edit"` pre-approves tools; `--permission-prompts none` (v2.1.259+) denies anything that would prompt instead of waiting, for scheduled/unattended jobs. Since v2.1.302 `-p` starts in Manual mode if nothing sets a mode, so un-approved calls are denied.
- SIGTERM exits with code 143 and leaves the turn unfinished; send SIGINT first to end the turn. `-p` waits for background work but stops idle waits after 10 min by default (`CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS`). `--max-budget-usd` caps spend and stops background work.
Permission modes [Verified] https://code.claude.com/docs/en/permission-modes
- `default`, `acceptEdits`, `plan`: expect a human. `dontAsk`: "Designed for unattended use", anything not pre-approved is denied ("for CI pipelines or restricted environments where you pre-define what Claude may do"). `auto`: a classifier reviews actions; "does not guarantee safety"; pauses and resumes prompting after 3 consecutive or 20 total blocks (so it can stall a headless run); broad `Bash(*)` allow rules are dropped. `bypassPermissions`: "Only use this mode in isolated environments like containers, VMs, or dev containers without internet access"; "offers no protection against prompt injection"; refuses to run as root/sudo outside a recognised sandbox; deny rules still apply; enable via `--permission-mode bypassPermissions` or `--dangerously-skip-permissions`.
- Example from the page: `claude -p "run the test suite" --permission-mode dontAsk --allowedTools "Bash(npm test)" "Read"`.
Sandboxing [Verified] https://code.claude.com/docs/en/sandboxing
- OS-enforced boundary for Bash commands only (file tools, MCP, hooks run outside it). Linux needs bubblewrap + socat; WSL2 yes, WSL1 no; native Windows unsandboxed. Writes limited to the working dir (+ added dirs); reads are broad by default (incl. ~/.ssh unless denied); network via a proxy with an empty allowed-domain list. Off by default; `sandbox.enabled: true`; `sandbox.failIfUnavailable: true` to refuse to run unsandboxed. Docker is incompatible with the sandbox (relevant to a docker-based SC2 match harness).
Remote Control [Verified] https://code.claude.com/docs/en/remote-control
- Connects claude.ai/code or the Claude mobile app to a session running on your machine; execution and files stay local; the machine makes outbound HTTPS only, no inbound ports. Needs a claude.ai subscription login (Pro/Max/Ultra/Team/Enterprise); API-key auth is not supported.
- `claude remote-control` (server mode) keeps a process running with a URL/QR; flags include `--name`, `--spawn same-dir|worktree`, `--capacity N` (default 32), `--permission-mode <mode>`, `--continue`. Interactive sessions reconnect automatically after sleep/network drop; server mode "gives up after roughly 10 minutes" of network outage and the process exits (needs a supervisor to restart). Permission prompts stay open until answered from any connected device. Transcript is stored on Anthropic servers while connected. Optional Trusted Devices.
Supported way to run a long unattended session safely (summary of the docs above; combination is my synthesis) [Likely]
- Dedicated non-root user in a container/VM or dev container (bypassPermissions needs that), OR the safer default of `claude -p ... --permission-mode dontAsk --allowedTools "<explicit narrow list>" --permission-prompts none` with sandboxing on (`sandbox.failIfUnavailable: true`), `--max-budget-usd` as a spend cap, `--output-format stream-json` logged to a file, `--bare` plus explicit `--settings`/`--mcp-config` so the run is reproducible, a supervisor (systemd) restarting with `--resume <session_id>`, and deny rules for anything destructive. Use Remote Control (server mode, `--permission-mode` set explicitly) only to watch/steer from a phone; it does not make the run unattended-safe by itself.
- Subscription usage limits: seat/plan 5-hour and weekly windows apply; on hitting them v2.1.234+ can wait and auto-continue after reset (`autoContinueAtUsageLimit`). [Verified] https://code.claude.com/docs/en/costs
